## 1차 리뷰 → `d5af38f`

**문제였던 것 (10건):**

- Dock 상태로 종료하면 세션 정리가 안 돌아 **Slidev 프로세스가 jadx보다 오래 살아남음**
- 창 닫기의 저장 프롬프트에서 "취소"해도 브라우저가 이미 죽어 **빈 패널**이 됨
- 덱을 겹쳐 열면 세션/브라우저 **누수**
- 탭 닫기(프로세스 종료 대기)와 `@멤버` 해석(클래스 디컴파일 유발)이 **EDT에서 돌아 UI 프리즈**
- marp가 멈추면 출력 EOF를 기다리느라 **타임아웃이 영원히 도달 불가**
- 전처리기가 `assets/@logo.png` 같은 **경로 속 `@`를 링크로 오변환**, `<style>` 블록 내 `@media` 오염, 저장마다 빈 줄 증가
- 정적 서빙의 형제 디렉토리 경로 탈출, Windows PATH 대소문자, CefApp 내부 클래스 하드코딩

**수정:** 세대 카운터 기반 열기, 정리 로직 스레드 분리, marp 출력 드레인 스레드, 전처리 lookbehind/`<style>` 스킵, 경로 검사 강화 등.

**⚠️ 이 수정이 만든 회귀 3건** — 같은 덱 재열기 시 새 세션의 파일을 옛 세션이 삭제 / CEF 초기화 예외 시 래치가 안 풀려 뷰 영구 비활성 / 백틱 속 `` `<style>` `` 언급만으로 이후 모든 `@` 링크 사망.

**수정:** 브릿지 소유권 토큰, EDT 착지 블록 try/finally, 인라인 코드 마스킹, 정리 단일 실행기 직렬화, `/jump` 최신-토큰-승리 워커 등.

**⚠️ 남긴 문제** — 종료 경로를 재배치하면서 "종료 시 처음 실행되는 코드"가 생김 (아래 크래시 ②③의 원인).

## 실사용 크래시 4건 (리뷰로는 못 잡은 것들)

jadx의 종료 흐름은 `windowClosing → 취소 가능한 프롬프트 → 백그라운드에서 closeAll()(플러그인 클래스로더 닫힘) → dispose() → System.exit(0)`. 이 순서와 JCEF의 macOS 특성이 겹쳐 크래시 4종이 순차적으로 드러남.

**① `TempWindowMac` 크래시 (Cmd+Q)** — CEF가 Cmd+Q를 가로채 즉시 종료하면서 살아있는 브라우저째로 네이티브 정리. → *수정:* 브라우저를 화면에서 떼고 닫은 뒤 jadx의 정상 종료 절차로 라우팅.

**② `util_mac::UpdateView` null 참조 (`e41b469`)** — 2차 리뷰가 정리를 `windowClosed`(dispose **후**)로 옮긴 회귀. dispose 시점에 브라우저가 화면에 붙은 채 살아있어 AWT가 죽은 네이티브 뷰를 갱신. → *수정:* 정리를 `windowClosing`(dispose **전**)으로 복원, 취소 케이스는 Reload 버튼으로 복구.

**③ `NoClassDefFoundError: ResultKt` (`102af1e`)** — 종료 중 클래스로더가 닫힌 뒤에 처음 실행되는 코드(람다 클래스, `runCatching` 실패 경로)가 그제서야 클래스 로드를 시도. 정리 스레드가 죽어 ①이 재발. jadx의 File→Exit 메뉴는 `windowClosing` 없이 종료한다는 것도 이때 발견. → *수정:* 종료 경로의 모든 클래스를 초기화 시점에 프리로드(이름 있는 클래스 + 웜업), 종료 코드에서 람다/`runCatching` 제거, Exit 메뉴 경로 커버.

**④ `JCEFApplication` 옵저버 크래시 (`67ac02f`)** — ③을 고치자 jcefmaven의 종료 훅이 **처음으로 진짜 CefShutdown을 완주**했는데, JCEF가 NSApplication에 스위즐해둔 이벤트 옵저버는 제거되지 않아 파괴된 자료구조를 참조. (그동안 ③의 에러가 이 크래시를 우연히 막고 있었음.) → *수정:* 종료 확정 시점에 `CefApp.state_`를 TERMINATED로 마킹해 CefShutdown 자체를 no-op화. 프로세스는 어차피 종료되므로 무해.

**교훈으로 굳어진 종료 3원칙** (변경 금지, 메모리에도 기록):
1. 브라우저 정리는 반드시 `windowClosing`에서 (dispose 전)
2. 종료 경로에서 새 클래스 로드 금지 (전부 프리로드)
3. 네이티브 CefShutdown은 실행하지 않는다

## 4차(최종) 리뷰 → `36e6e4c`

*3차 리뷰는 크래시 대응 도중 실행했으나 Claude 세션 중단으로 결과 없이 종료 — 안정화 후 재실행한 것이 이 4차.*

**문제였던 것 (10건 + 2건):**

- 정리 훅이 "CEF 브라우저 생성 성공 후"에만 설치 → 브라우저 폴백 사용자는 종료 시 청소 없음
- Windows에서 프로세스 종료가 cmd.exe 껍데기만 죽임 (node 생존)
- nvm 버전 정렬이 문자열 기준 (v9 > v18)
- 열기 도중 종료 시 준비 중 세션 고아 / prepare 예외 시 세션 누수 / createBrowser 실패 시 CefClient 누수 / 정리 스레드의 stale 읽기(@Volatile 누락)
- 연타 열기 시 느린 쪽이 빠른 쪽의 서빙 상태를 덮어쓰는 경쟁 / Slidev 포트 TOCTOU
- 메뉴 열림 중 화살표 키 삼킴
- 죽은 코드 2건 (`detachBrowser`, `isDocked`)

**수정:** 훅 조기 설치, 프로세스 트리킬, 숫자 정렬, pendingSession 추적, 브릿지 publish/clear 원자화 + EDT 승자 게시, slidev 배너 URL 파싱(ANSI 제거), 키가드 메뉴 조건 등. 이 리뷰는 종료 3원칙 경로를 검토 후 **"올바르니 유지"** 판정.
